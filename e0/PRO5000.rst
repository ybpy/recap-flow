PRO5000 开发、发布与 E0 预实验
============================

本版本以 cyy_dev2 / 9-pro5000rdma / 单节点八张 RTX PRO 5000 72GB 为执行平台。
历史 A800 发布目录保留，只用于追溯。所有 TIONE 任务仍由用户手动启动。

环境与挂载
----------

代码、两套 uv 环境、uv Python 和 LIBERO 子模块位于 /mnt/code/recap-flow。
训练 Python 3.11.9；仿真 Python 3.10.12，两者均由项目 .uv-python 提供。
依赖锁为 e0/environment/train.lock 和 libero.lock，uv 固定 0.10.4，copy 安装。
新镜像补装 libegl1、libopengl0；实际系统包版本见 migration/audit.json。
扩容镜像必须包含验收过的系统包、宿主驱动匹配的图形加载方式和 HCCL 库。

开发机及任务使用如下固定路径：

* /mnt/code/recap-flow：版本化代码、环境、解释器和仿真资产；训练期间冻结。
* /mnt/models：pi05_base 与 actor tokenizer，读取。
* /mnt/datasets：原始 RLDS 和旧转换数据，审计时读取；不原地修改。
* /mnt/recap-flow-runtime/datasets：SFT 快照、rollout 与独立重标快照。
* /mnt/recap-flow-runtime/assets：norm stats、critic 权重/tokenizer、图形库。
* /mnt/recap-flow-runtime/runs：恢复 checkpoint、EMA 候选、指标及运行溯源。
* /mnt/recap-flow-runtime/smoke：验收配置、日志及闭环产物，不进入实验结果。
* /mnt/recap-flow-runtime/reports：审计及分析；releases：冻结发布记录及副本。

SFT 固定 1,693 episodes / 273,465 frames。
norm stats 已计算，迁移只校验，不重新计算。
完整数据校验和与 Python 构建信息由 migration-audit 记录。

通信由 e0/environment/pro5000.sh 显式设置。HCCL 2.30.4.1 的 libnccl.so
校验失败立即退出；不会自动回退旧 NCCL。动态库路径排除系统 Python 3.12
Torch、TensorRT 和 CUDA 13 compatibility 路径。正式运行清除代理并离线加载。
该配置只验收单节点通信，不代表跨节点 RDMA 已验证。

需要联网安装时，在当前 shell 设置 localhost:11805 的 HTTP/HTTPS 代理，
NO_PROXY 加入 localhost、127.0.0.1、::1 和 mirrors.tencentyun.com。
代理依赖本机 cyy_dev2_tunnel SSH 转发；它不是训练运行依赖。

验收与启动
----------

入口环境变量（键值对）：

::

  E0_PLATFORM: pro5000
  CUDA_VISIBLE_DEVICES: 0,1,2,3,4,5,6,7
  RECAP_RUNTIME: /mnt/recap-flow-runtime
  NCCL_PCI_SEARCH_FIX: "0"
  MUJOCO_GL: egl
  OMP_NUM_THREADS: "4"
  WANDB_MODE: disabled
  NVIDIA_DRIVER_CAPABILITIES: compute,utility,graphics

LD_PRELOAD 和其余通信变量由统一入口设置并校验。
完整验收：

::

  cd /mnt/code/recap-flow
  E0_PLATFORM=pro5000 CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
    bash scripts/e0.sh smoke --platform pro5000 \
    --output /mnt/recap-flow-runtime/smoke/e0-pro5000-v1-deterministic --phase all

验收包括八卡运算、集合通信、八卡 EGL、双环境 schema、actor 100 次实际更新、
两种 critic 各 20 次更新、断点恢复、采集/转换/critic/标注/actor/评测闭环、
从官方初始状态重放完整动作历史的检查。各阶段 passed 文件才是通过凭据。
恢复比较 batch、RNG、参数、optimizer 和 EMA，不能通过重置训练绕过。

P1：seed 42 SFT 预实验，50,000 更新，batch 256，FSDP=4，warmup 10,000，
此后 LR=5e-5，EMA=0.999，clip=1，condition dropout=30%。
使用四套完整 demo，按帧 shuffle；候选 EMA 为 30k / 40k / 50k。

::

  cd /mnt/code/recap-flow
  E0_PLATFORM=pro5000 bash scripts/e0.sh pilot-sft --platform pro5000 \
    --output /mnt/recap-flow-runtime/jobs/pilot-s42-sft-50k-pro5000.json
  E0_PLATFORM=pro5000 CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
    bash scripts/e0.sh run /mnt/recap-flow-runtime/jobs/pilot-s42-sft-50k-pro5000.json

同一任务恢复只把 run 改为 resume，其他参数及环境保持相同。
运行目录：/mnt/recap-flow-runtime/runs/pilot-s42-sft-50k-pro5000。
metrics.jsonl 记录每次更新；recovery 保存完整状态；candidates 保存候选 EMA 和资产。
本地长任务仅在所有验收通过且发布记录完成后启动。

后续顺序
--------

P2：训练结束后串行评估三个 EMA，每个 40 任务 × 50 官方初始状态，共 6,000 次。
任务宏平均成功率选模，平局较早；八卡训练期间不同时做 GPU 评测。

P3：选定 SFT 在 Long 10 任务各 50 次采集，共 500 次。独立开发轨迹供 critic 验证。
Critic 比较冻结/全量以及 10k/20k cosine 总预算。不同总预算从固定初始化独立运行。

P4：共享 R1 数据、critic 和标签，比较 base_reset 与 warm_start；开展标签与条件响应诊断。
P5：各分支采集自己的 R2，继续 E0；用证据决定信号改进与 actor 利用方式的四格比较。
正式三种子预算在预实验后冻结，不自动扩展矩阵。

研究诊断入口
------------

rollout 在 decisions/ 写完整 H=10 块、实际执行起止位置、决策编号、采样 seed、
policy_id 和 checkpoint。轨迹 NPZ 仍只包含实际执行的动作，兼容原训练转换器。

research-prepare 从选定 SFT 的 Long 开发结果中固定选择 init ID 0--9，构造
200 个观测与 40 个预设时间分位锚点。缺失时报告错误，不按表现替换样本。
research-labels 比较相同帧池上的 critic 排序和阈值标签变化；一致性不称为置信度。
research-conditions 查询 positive / negative / unconditional，各四组噪声；
比较真实七维动作前五步。unconditional 采用训练 condition dropout 的无条件提示。
research-loss 在 R1/R2 自主训练帧上使用相同 flow 噪声，比较原标签与任务内打乱
标签的原始训练 loss；这属于池内条件利用诊断，不能称为留出集泛化评测。
research-branch 执行 4 候选 × 3 配对续跑种子，固定 SFT 续跑策略及原剩余预算。
replay-check 验证重建控制器历史后，观测、图像及固定后续动作可重现。

研究输出使用 research/ namespace，不生成可自动加入训练的数据集；
训练入口拒绝 development、final、research 和未知来源混入训练。
研究结果须等待选定 SFT、R1 critic/actor 后产生，不能用 smoke 结果替代。

发布与镜像
----------

e0-pro5000-v1 发布记录绑定代码提交、环境锁、解释器、系统包、HCCL、图形库、
数据和统计身份。用户固化镜像后再填实际 URI/digest，不能沿用旧 A800 镜像标识。
扩容必须挂载独立代码/环境发布副本到相同绝对路径，不能挂载可变开发目录。
一个新增八卡节点运行一个独立实验；新增节点先做真实更新和恢复验收。

Determinism: PRO5000 pins Ring / Simple, cuBLAS workspace and deterministic XLA
options. Autotune level 1 selects a deterministic candidate rather than timing
selection. Conflicting frozen flags are rejected; full-state recovery is the gate.
